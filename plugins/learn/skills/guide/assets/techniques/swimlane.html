Swimlane

What it is: A process diagram split into horizontal rows ('lanes'), one per role, team or system. Each step sits in the lane of whoever does it.

What it does for the reader

  • Shows who is responsible for each step, not just the order.
  • Makes hand-offs between roles visible (a step moving to another lane is a hand-off).
  • Exposes work that happens separately or later, such as async jobs.
Best forWork split across roles or services
Avoid whenOne role — use flow
FormatsHTML/SVG · React · Mermaid

Example: Creating and sharing a link: the user submits, the API server takes a code, the key service refills its batch, analytics count clicks later in their own lane.

How to read it
  • Each row is one actor; its name is on the left.
  • Numbered cards show the order across all lanes.
  • When consecutive cards jump lanes, work is handed off.
Notes on this example
  • One row per role; numbered cards show order.
  • The analytics lane runs later and separately — async work is easy to spot.

How to build it: SVG: one coloured band per lane, step cards placed by lane (row) and order (column). Markdown: Mermaid flowchart with one subgraph per lane, or a table (step · lane).
